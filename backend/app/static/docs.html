SIM SMS Gateway API Reference

Transform any Android smartphone into an ultra-reliable, high-throughput, and TCRA-compliant SMS gateway with automated carrier routing, per-SMS modifications, and signed webhook dispatches.

⚡

Sub-Second Queueing

Database-backed transactional queue with FIFO prioritization and instant dispatch to available Android nodes.

🇹🇿

Tanzania MNO Routing

Automatic detection for Vodacom, Airtel, Tigo/Yas, Halotel & TTCL with SIM bundle optimization and DND anti-spam protection.

🔐

Hardware Cryptography

Hardware-backed AES-256-GCM encryption on device nodes, HMAC-SHA256 signed webhooks, and tenant-scoped data isolation.

ℹ️
Production API Base URL All API requests in production should be addressed to https://sms.edusphere.co.tz/api/v1 over TLS 1.3 with standard JSON request bodies.

5-Minute Quickstart Guide

Follow these 4 simple steps to start sending SMS messages through your hardware phone gateway:

1

Install App & Pair Android Device

Install the SIM SMS Gateway app on your Android smartphone. On your web dashboard, click Connect Android Smartphone, generate an 8-character pairing code, and enter it into the app.

2

Create a Client API Key

Navigate to API Keys in your dashboard and generate an API key with sms:send and sms:read permission scopes.

3

Submit Your First Outgoing SMS

Dispatch a simple cURL or Python POST request to /api/v1/messages:

curl -X POST "https://sms.edusphere.co.tz/api/v1/messages" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"recipient": "+255712345678", "body": "Welcome to our service!"}'
4

Listen for Real-Time Webhooks

Register your HTTPS webhook endpoint to receive immediate callbacks with delivery timestamps and carrier report codes.

Authentication & API Keys

All API requests must authenticate using an API Key or JWT Bearer Token in the HTTP Authorization header:

Authorization: Bearer sms_live_9a8f4c2e...

Alternatively, you can pass the key in the custom header X-API-Key: <key>.

Available Permission Scopes

Scope Access Level Description
sms:send Write Allows queuing single SMS and bulk message bundles.
sms:read Read Allows checking message delivery status and incoming inbox SMS.
sms:modify Write Allows modifying or cancelling queued messages before transmission.
device:manage Admin Allows pairing, pinging, and managing Android gateway hardware nodes.
webhooks:manage Admin Allows creating and editing webhook subscriptions and secret tokens.
POST /api/v1/messages
scope: sms:send

Submits an outgoing SMS to the transaction queue. Automatically detects the recipient's Tanzania carrier, validates GSM-7 character sets, and routes to the best SIM card.

Request Body

Field Type Description
recipient * string Phone number in E.164 (e.g. +255712345678) or national format (0712345678).
body * string SMS message text. Multi-part concatenation is supported automatically.
priority integer Priority level 1 (highest/OTP) to 10 (bulk marketing). Default: 5.
sim_slot integer Force specific SIM: 1 for SIM 1, 2 for SIM 2. Default: null (auto-detect based on carrier).
client_reference string Your internal transaction or tracking reference ID.

Broad rural coverage across continental Tanzania.

GSM-7 vs UCS-2 Character Encoding

Understanding SMS character sets prevents unexpected multi-part charges:

Encoding Standard Characters per 1st Segment Characters per Subsequent Segment Supported Characters
GSM-7 (Standard) 160 characters 153 characters English alphabet, numbers, punctuation, standard Swahili text.
UCS-2 (Unicode) 70 characters 67 characters Emojis (🚀, 😊), Arabic/Swahili loan characters, accented characters.

Webhook Event Dispatch

Whenever a message changes state (queued, sent, delivered, failed) or an inbound SMS arrives, the gateway posts an HTTPS JSON payload to your registered webhook URL.

Webhook Delivery Headers

X-Event: message.delivered
X-Signature: c89a421b8f042e88a0e81b...
X-Timestamp: 1792866940
Content-Type: application/json

Verifying the HMAC-SHA256 Signature

Always verify the X-Signature header in your backend code to protect against spoofing:

# Python verification example
import hmac, hashlib

def verify_webhook(raw_body_bytes, signature_header, secret_key):
    expected = hmac.new(secret_key.encode(), raw_body_bytes, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature_header)
